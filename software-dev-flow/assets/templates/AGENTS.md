# <项目名> · 开发协作约定(Claude Code / Codex 共用入口)

> `CLAUDE.md` 软链到本文件,两个工具读同一份。**真相源在文件里,不在对话里。**
> 本文件是**运行时合同**:精要规则 + 门禁命令区 + 约束 + 指针。完整详规在 `flow/规范/`。

## 目录地图(哪个文件夹放什么)
- 根级 `flow/` — 唯一控制层(项目"怎么跑"):`charter.md` 目标 / `plan.md` 计划=契约 / `进展.md` 进展日志(顶部=交接棒)/ `decisions.md` 决策日志 / `踩坑记录.md` 问题与经验库 / `releases.md` 变更日志 / `tasks/` 任务卡 / `规范/` 方法论详规
- 根级 `docs/` — 集中内容层(项目"做出什么"):`requirements/` 需求 · `architecture/` 架构 · `contracts/` 跨模块契约(真相源)/ `modules/` 模块说明 · `testing/` 测试策略与报告 · `runbooks/` 部署发布手册 · `reviews/` 评审结论
- `<子项目>/`、`src/` 或 `scripts/` — 代码、测试、构建与运行配置;有独立职责的子项目用局部 `AGENTS.md` + `CLAUDE.md` 记录本模块规则
- `DESIGN.md` — (可选)设计 / 创意决策
- **判据**:协调 / 推进总体项目的 → 根级 `flow/`;需要统一发现的知识、契约和方案 → 根级 `docs/`;代码 → 对应子项目。默认不在子项目重复建 `flow/` 或 `docs/`

## 质量门禁命令区(唯一真相源)
> 初始化时从项目配置探测填入;构建方式变了**先改这里**再跑门。探测不到的门标 TODO,禁止编造。

- **构建**:<探测填入,如 `npm run build` / `make` / `msbuild ...`>
- **测试**:<探测填入,如 `npm test` / `pytest` / `go test ./...`>
- **静态检查**(lint / typecheck,项目没配则写"未配置,此门免"):<探测填入>
- **评审**:换另一个模型评审(审稿模型 ≠ 产出模型),结论落 `docs/reviews/` 或任务卡

## 多子项目边界
- 前端、后端、共享包等共享同一仓库和总体目标时,共用根级 `flow/`、`docs/` 和 hook。
- 每个有独立职责的子项目只建局部规则入口(含**本模块**门禁命令),不复制总体计划、交接或文档体系。
- 已有 README、生成文档或必须紧贴代码维护的说明可以留在模块内,但要从根级 `docs/README.md` 建索引。
- 子目录有独立 `.git`、版本、发布或团队边界时,按独立项目处理;完整判断见 `flow/规范/多子项目结构.md`。

## 开工前必读
1. `flow/charter.md` — 目标 / 范围 / 约束 / 成功标准 / 技术栈与质量基线
2. `flow/plan.md` — 当前计划(**契约**,未确认不要偏离)
3. `flow/进展.md` **顶部一条** — 上一棒交接棒(做了啥 / 产出路径 / 门禁状态 / 下一步)
4. 你被分配的任务卡:`flow/tasks/<...>.md`
5. 跨模块接口先读真相源:`docs/contracts/`
6. 当前目录若有局部 `AGENTS.md`,同时遵守其中的职责边界和模块约束

## 开工约定
- **每任务一分支**:`<type>/T<编号>-<短描述>`(如 `feat/T03-用户登录`、`fix/T07-登录超时`)。
- **契约先行**:跨模块接口先确认 `docs/contracts/` 再实现;改接口先改契约文档,再改两端代码。
- **测试同棒**:新代码与对应测试同一棒交付;修 bug 先补一条能复现的测试。

## 收工前必做
1. **过门禁**:按「质量门禁命令区」跑构建 / 测试 / 静态检查,评审换模型;结果**如实**记录(未跑写未跑)。门禁细节见 `flow/规范/质量门禁.md`。
2. 在 `flow/进展.md` **最上面追加一条进展**(做了什么 / 为什么 / 怎么理解 / 产出路径 / 门禁状态 / 问题→解决 / 下一步),**并把这条同时贴在回复里**——这条就是交接棒。
3. 决策追加 `flow/decisions.md`;问题 / 踩坑追加 `flow/踩坑记录.md`。
4. 文档自检:本轮若动了结构 / 契约 / 方向 / 命令,主动提议更新本文件(见「文档维护」)。

## 核心约束(铁律)
- **契约先行**;实现与契约不一致时以契约为准修实现,不悄悄偏离。
- **测试同棒**;修 bug 先写能复现的测试。
- **门禁不过不收工**(构建 / 测试 / 静态检查 / 评审全绿或用户明确豁免);红了不绕过,严禁注释测试、降低断言、只跑改动文件冒充全量。
- 审稿模型 ≠ 产出模型(交付前换另一个模型评审)。
- 产出落文件,不留在对话里。
- 先 plan 后 act,计划即契约;要改先改 `flow/plan.md`。
- 一会话一焦点。
- 单仓只保留一套总体控制层;模块任务通过任务卡和产出路径区分。
- 产物本身是真相唯一来源;文档只补"看产物看不出的为什么"。
- 解决问题从根本上解,不打补丁。
- 进展条 / 交接只带「指针 + 增量」,不重抄内容。
