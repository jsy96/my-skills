# 视觉资产与飞书写入

## 视觉生成原则

1. 先确认风格、数量、比例、交付位置和是否允许调用付费模型
2. 批量生成前保留一个可回退的已确认版本
3. 所有图片使用独立目录，不覆盖旧图
4. 小红书正文图默认 3:4，1200×1600
5. 生成后用文件命令或脚本校验尺寸、格式和数量
6. 建议生成 contact sheet 方便用户快速确认

## 代码原生图片

适合卡片、流程图、结构图、风格变体和可重复视觉系统：

- 可用 SVG、HTML/CSS、Python + Pillow
- 字体优先系统中文字体；生成前确认可用字体
- 固定随机种子，保证可复现
- 每张图保留生成脚本或 SVG 源文件
- 避免把 API Key、私有链接或用户数据写入资产

若用户要求 AI 位图风格且环境有可用图片生成能力，先说明数量和消耗；确认后再生成。

## 飞书写入流程

使用环境已有的 `lark-doc` 能力时，按其规则执行。核心顺序：

1. 初始化创作草稿并记录 `workspace`、`draft_path`
2. 写完整 XML：
   - 唯一 `<title>`
   - 标题层级连续
   - 本地图片用 `path="@./..."`
   - 缺事实 / 缺素材保留 `[待核]` / `[待补]`
3. 运行 parse，确认 `assessment.status` 为 `passed`
4. 创建飞书文档
5. 检查 `warnings`；若有局部失败，不新建文档，按最小范围修复
6. fetch 回查：
   - 文档标题
   - 正文完整性
   - 标签
   - 图片数量与顺序
   - 视觉版本说明
7. 交付文档链接和回查结果

## 常见问题处理

- Keychain / 授权错误：优先按 `lark-shared` 指引修复；需要人工授权时给出明确步骤
- 图片上传失败：不要重复新建文档；对已有文档做最小修复
- XML 解析失败：只修复诊断指向的局部问题
- 生成效果不符：输出对比图或核验清单，请用户人工确认，不要无限重试
- 多版本并存：每版一个文档，标题注明风格，原链接不做覆盖
