# Self-media Reuse Workflow

将已核实的内容资产复用到多个自媒体形态，保持事实、个人语气和交付边界一致。典型链路是：素材学习 → 公众号文章 → 小红书图文 → 口播稿 / Vox 分镜 → 多风格视觉重制 → 飞书另存与回查。

## 必守原则

1. **先方案、后消耗**：任何生成、修改文档、批量生图、调用付费 API 或推送外部仓库前，先给用户简明方案并获得确认。用户确认当前方案后，不重复追问；发现范围变化时再确认。
2. **素材优先**：先完整读取用户给出的文章、讲义、纪要或飞书文档。不要把模板当作事实来源。
3. **真实边界**：保留真实案例、个人语气和可核事实。缺事实写 `[待核]`，缺素材写 `[待补]`，禁止编造数据、引用、经历或效果。
4. **一稿一用**：改风格、换平台或重制视觉时默认新建资产目录和新的飞书文档，不覆盖用户已确认版本。
5. **回查交付**：写入飞书后必须回查标题、正文结构、标签、图片数量和关键占位符，再交付链接。
6. **停止条件**：安装、授权、生成或上传连续失败时，不要无限重试。给出人工核验步骤、当前已完成状态和下一步可选方案。

## 总体流程

1. **确认任务形态**
   - 公众号文章：读 `references/content-contracts.md`
   - 小红书图文：读 `references/content-contracts.md`
   - 口播稿 / Vox 分镜：读 `references/video-handoff.md`
   - 视觉重制 / 飞书写入：读 `references/visual-and-feishu.md`

2. **建立内容底座**
   - 目标读者是谁、正带着什么任务来读
   - 核心观点、真实案例、可迁移方法、限制条件
   - 保留作者语气中的口头禅、节奏和具体经历，不把个人经验泛化成绝对承诺
   - 为每个事实判断来源；无来源就使用 `[待核]`

3. **输出确认包**
   - 先给受众、核心观点、结构、视觉方向、消耗范围和交付物
   - 用户确认后再生成完整内容或修改外部系统
   - 若用户只要求方案或脚本，不启动付费图片 / 视频生成

4. **按平台合同生成**
   - 每个平台使用其交付清单，不混用格式
   - 标题、首屏、正文和结尾必须兑现同一个承诺
   - 生成后先自查事实、结构、口语感、夸张承诺和占位符

5. **资产与文档**
   - 新建独立目录保存图片或视频草稿
   - 飞书新文档使用独立 XML 草稿，解析通过后再创建
   - 回查通过后只交付用户需要的链接和简短状态

## 常用路由

- 用户提供飞书文档 / Wiki URL：优先使用本环境已有的 `lark-doc` 能力读取；遇到认证问题按其指引处理。
- 公众号插图：可使用已有的 `ian-xiaohei-illustrations` 风格；没有该能力时输出 shot list 和生成提示词。
- 小红书封面 / 正文视觉：可使用已有的 `gbro-cover-design`、`punk-cover` 或本地确定性绘图；必须先确认风格。
- Vox 视频：遵循 `references/video-handoff.md`，真实旁白和人工确认优先于任何付费生成。
- 简单几何、卡片、流程图、风格变体：优先用 SVG / HTML / Python + Pillow 等代码原生方式生成，避免不必要的模型消耗。

## 交付状态模板

完成后说明：

- 已生成的内容类型和数量
- 本地资产目录
- 飞书文档链接
- 回查结果：标题、正文、标签、图片数量
- 未关闭缺口：`[待核]` / `[待补]` / 授权或素材问题
